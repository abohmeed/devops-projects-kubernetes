Being `Available` only means Velero is ready to work: nothing has been backed up yet. The worst day
for an application is not a dropped database table, it is someone deleting the whole thing: the
Deployments, the Secrets, the Services, and the volume where the data lives. This handout takes a
full backup of the WeatherApp with Velero, deletes the entire namespace on purpose, and restores it
back onto the same cluster.

## Before you start

You need the cluster, the WeatherApp (with `alice` registered), and Velero (installed with a
backup location reading `Available`) from the previous handout. No `Backup`, `Restore`,
`DataUpload` or `DataDownload` object should exist yet, and no leftover `VolumeSnapshot`.

```bash
export AWS_PROFILE=<your-aws-profile>
cd <your-s05-folder>
```

## Step 1 - Confirm the app is up

```bash
kubectl get svc -n weatherapp weatherapp-ui
```

Open the hostname and log in as `alice`. This is the state the backup protects.

## Step 2 - Take the backup

```bash
velero backup create weatherapp-golden --include-namespaces weatherapp --snapshot-move-data --wait
```

```
Backup request "weatherapp-golden" submitted successfully.
Waiting for backup to complete. You may safely press ctrl-c to stop waiting - your backup will continue in the background.
```

then

```
Backup completed with status: Completed. You may check for more information using the commands `velero backup describe weatherapp-golden` and `velero backup logs weatherapp-golden`.
```

`--include-namespaces weatherapp` limits the backup to one namespace, since the namespace has been
this app's unit since it was split apart. `--snapshot-move-data` is the flag doing the real work:
instead of leaving an EBS snapshot sitting in your account, it has Velero move the volume's actual
data into the backup bucket. `--wait` just keeps the command in front of you until the backup
finishes.

## Step 3 - Watch the data move

```bash
kubectl get datauploads -n velero
```


Velero took a CSI snapshot of the volume, a data mover pod copied that snapshot's contents into S3,
and then the temporary snapshot was removed:

```bash

```

## Step 5 - Find the bucket

Open a second terminal: the profile must be exported again there, since a fresh shell has no
default:

```bash
export AWS_PROFILE=<your-aws-profile>
export BUCKET=$(aws s3api list-buckets --query "Buckets[?starts_with(Name, 'weatherapp-velero-')].Name" --output text)
aws s3 ls "s3://$BUCKET/"
```

```
                           PRE backups/
                           PRE kopia/
```

`backups/` holds the Kubernetes objects and the backup's own record; `kopia/` holds the volume data
you just watched move.

```bash
aws s3 ls "s3://$BUCKET/backups/weatherapp-golden/"
```

## Step 6 - Cause the disaster

Back in the first terminal:

```bash
kubectl delete namespace weatherapp
```

```
namespace "weatherapp" deleted
```

Everything in that namespace goes with it: the pods, the Secrets, Helm's own release records, the
load balancer, and (since the database claim's reclaim policy is `Delete`) the EBS volume
underneath it too.

```bash
kubectl get pv
```

```
No resources found
```

## Step 7 - Restore it

```bash
velero restore create weatherapp-restore-1 --from-backup weatherapp-golden --wait
```

```
Restore completed with status: Completed. You may check for more information using the commands `velero restore describe weatherapp-restore-1` and `velero restore logs weatherapp-restore-1`.
```

```bash
kubectl get datadownloads -n velero
```

```
NAME                         STATUS      STARTED   BYTES DONE   TOTAL BYTES   STORAGE LOCATION   AGE   NODE
weatherapp-restore-1-vx8gk   Completed   35s       218438055    218438055     default            48s   ip-192-168-53-94.ec2.internal
```

You never pointed the restore at a snapshot yourself: the backup already knew where its own data
was sitting.

## Step 8 - Check what came back

```bash
kubectl get pods -n weatherapp
kubectl get pvc -n weatherapp
```

The pods start `ContainerCreating` at first; rerun until all seven are `1/1 Running`:

```
data-weatherapp-auth-mysql-0   Bound    pvc-3010ffd0-5f1c-4c93-8f3c-b7266c5a4cee   8Gi        RWO            ebs-csi-default-sc   <unset>                 52s
```

```bash
helm list -n weatherapp
```

`weatherapp-auth`, `weatherapp-ui` and `weatherapp-weather` all come back `REVISION 1`, `deployed`,
`APP VERSION 3.0.0`: Helm keeps its release records as Secrets inside the namespace, and Velero
restored those Secrets along with everything else.

## Step 9 - Prove it works

```bash
kubectl get svc -n weatherapp weatherapp-ui
```

A **new** hostname comes back, since the old load balancer was deleted along with the namespace. In
production you would point a DNS alias record at whatever the current load balancer happens to be, so
a change like this would be invisible to your users. Open the new hostname and log in as `alice`: it
works, meaning her password check just ran against the restored `users` table.

## Stopping here?

The restored WeatherApp is fine to leave running if you are continuing to the next handout, which
restores this same backup onto a second cluster. To stop entirely:

```bash
kubectl delete namespace weatherapp
helm uninstall velero -n velero
kubectl delete namespace velero
aws s3 rb "s3://$BUCKET" --force
aws iam delete-role-policy --role-name weatherapp-velero --policy-name velero-s3
aws iam delete-role --role-name weatherapp-velero
eksctl delete cluster -f cluster.yaml --wait
```

## Traps

::: gotcha
**A second terminal fails with `Unable to locate credentials`.** A new shell has no `AWS_PROFILE`
exported and no default profile. Export it again there before running any `aws` command (Step 5).
:::

::: gotcha
**The backup ends `PartiallyFailed` or `Failed`.** Usually there are no `node-agent` pods running, or
the backup storage location is not `Available`. Read `velero backup describe weatherapp-golden
--details` and `velero backup logs weatherapp-golden` for the exact cause before retrying.
:::

::: gotcha
**`velero backup create` fails with `BackupAlreadyExists`.** A backup with this name already exists
from an earlier attempt. Delete it (`velero backup delete weatherapp-golden`) before creating a new
one with the same name.
:::
