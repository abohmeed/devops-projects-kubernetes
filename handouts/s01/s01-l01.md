This course is project driven. Instead of teaching Kubernetes concepts from the ground up, it takes
a working knowledge of Kubernetes and puts it to work on the deliverables a DevOps engineer is
actually asked to build: a cluster, applications running on it, a delivery pipeline, and a way to
recover it when something goes wrong. Theory shows up only where a lab needs it, not as a chapter of
its own.

## The five sections, in order

Each section builds on the one before it. There is no need to jump ahead: the cluster from section
one is what section two deploys onto, and so on.

| Section | What it builds | Main tools |
|---|---|---|
| 1. Cluster foundations | The same Kubernetes cluster on AWS, three different ways, then a comparison of the three | kOps, Amazon EKS (via eksctl), kubeadm on EC2 built with Packer and Terraform |
| 2. Provisioning applications | The same application deployed onto that cluster, three different ways, ending with an operator built for it | Kustomize, Helm (including a blue/green release), Kubernetes operators |
| 3. The WeatherApp project | A small microservices application: a UI, an authentication service, a weather service, and a MySQL database | Docker Compose (local), then Helm on Kubernetes |
| 4. Continuous delivery | An automated pipeline for the WeatherApp: a CI user for both EKS and non-EKS clusters, then build, push, stage, and promote to production | GitLab CI/CD |
| 5. Disaster recovery | Backing up and restoring the application's data, first in place, then into a second cluster | EBS snapshots, Velero |

## Who this course is for

Engineers who already know what a pod and a Deployment are, and want to apply that knowledge end to
end. That covers two situations equally well: moving into a DevOps role, or already holding one and
wanting concrete projects to point to. If pods and Deployments are still new territory, a Kubernetes
fundamentals course first will make everything here far easier, since this course applies Kubernetes
rather than teaching its building blocks.

## Prerequisites checklist

Work through this list honestly before the hands-on lectures start. Nothing here is taught from
scratch in this course.

| Area | What you should already be comfortable with |
|---|---|
| Linux shell | Navigating directories, editing files, running commands, reading output |
| Kubernetes | Pods, Deployments, Services, and enough `kubectl` to inspect and change what is running |
| AWS | EC2, S3, IAM, and Route 53 at a working level |
| Docker | Images, containers, and registries |
| Terraform and Ansible | Helpful, not required. Whatever this course uses from them is explained as it comes up |

## Where the hands-on work runs

Every hands-on lecture runs on your own AWS account, in the **us-east-1** Region. If you work in a
different Region, substitute it wherever a Region comes up in a lecture. You will need:

- Administrator access on that AWS account.
- The AWS CLI installed and configured with a profile that has administrator permissions.

::: gotcha
The clusters, load balancers, and NAT gateways built across this course cost money for as long as
they exist, not just while you are using them. Every hands-on lecture ends by tearing down what it
built, and you should do the same before moving to the next one. Leaving a cluster or a NAT gateway
running between sessions is the single easiest way to get an unpleasant AWS bill.
:::
